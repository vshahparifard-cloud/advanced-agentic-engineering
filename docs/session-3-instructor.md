# راهنمای مدرس — مهندسی MCP و اتصال ابزارها

مدت: ۱۲۰ دقیقه؛ هر اسلاید ۵ دقیقه. فعالیت‌های عملی در زمان همین اسلایدها انجام می‌شوند، نه علاوه بر آن. پیش از کلاس نصب ابزارها را طبق راهنمای آزمایشگاه انجام دهید.

در صورت نیاز به استراحت، پنج دقیقه از بخش بحث پایانی کم کنید و آن را در زمان جلسه ثبت کنید.

## 1. مسئله: وب‌سایت قابل استفاده برای عامل — دقیقهٔ 0 تا 5

- HTML برای انسان طراحی شده است
- عامل به عملیات معنادار و ساخت‌یافته نیاز دارد
- MCP لایهٔ اتصال است، نه خود مدل

**راهنمای اجرا و بحث:** جستجوی جلسهٔ دوره را مثال بزنید. ابزار search_lessons باید نتیجهٔ محدود و قابل استناد بدهد؛ ابزار execute_anything دامنهٔ غیرضروری ایجاد می‌کند.

## 2. Host، Client و Server — دقیقهٔ 5 تا 10

- Host تجربه و سیاست کاربر را مدیریت می‌کند
- Client اتصال پروتکل به یک server را نگه می‌دارد
- Server قابلیت‌های محدود کسب‌وکار را ارائه می‌کند

**راهنمای اجرا و بحث:** نمودار سه لایه را روی تخته بکشید. وجود server به معنی مجوز خودکار استفاده از تمام داده‌ها نیست. policy میزبان و کنترل سمت server هر دو لازم‌اند.

## 3. چرخهٔ اتصال — دقیقهٔ 10 تا 15

- ابتدا initialize و مذاکرهٔ قابلیت‌ها
- سپس کشف tools و resources
- فراخوانی فقط بعد از آماده شدن اتصال

**راهنمای اجرا و بحث:** آزمایشگاه از SDK رسمی استفاده می‌کند تا چرخهٔ پروتکل را دستی و ناقص نسازد. در log، initialize را قبل از call_tool نشان دهید. نسخهٔ پروتکل را hard-code نکنید.

## 4. Tool چه قراردادی دارد؟ — دقیقهٔ 15 تا 20

- نام کوتاه و توضیح دقیق برای انتخاب
- schema ورودی محدود و قابل اعتبارسنجی
- خروجی کوچک با شناسه و منبع

**راهنمای اجرا و بحث:** search_lessons یک query و limit می‌گیرد. limit صدها هزار نتیجه را نمی‌پذیرد. از فراگیر بخواهید رفتار query خالی را پیش از نوشتن server مشخص کند.

## 5. Resource و Prompt — دقیقهٔ 20 تا 25

- Resource دادهٔ خواندنی با URI مشخص است
- Prompt قالبی است که کاربر می‌تواند انتخاب کند
- Tool یک عملیات قابل فراخوانی است

**راهنمای اجرا و بحث:** فهرست دوره را resource و جستجو را tool قرار دهید. تمایز بر مبنای نحوهٔ استفاده است؛ read-only بودن ابزار آن را خودکار به resource تبدیل نمی‌کند.

## 6. STDIO در برابر HTTP — دقیقهٔ 25 تا 30

- STDIO برای فرایند محلی ساده است
- Streamable HTTP برای سرویس شبکه‌ای مناسب است
- احراز هویت HTTP را به STDIO کپی نکنید

**راهنمای اجرا و بحث:** نمونهٔ جلسه STDIO است و سرویس عمومی شبکه ایجاد نمی‌کند. برای HTTP، Origin، TLS، نشست و authorization لازم‌اند. این تمرین ادعای سرور تولیدی اینترنتی ندارد.

## 7. انضباط stdout — دقیقهٔ 30 تا 35

- پیام پروتکل از stdout عبور می‌کند
- log عادی روی stdout اتصال را خراب می‌کند
- برای log محلی از stderr استفاده کنید

**راهنمای اجرا و بحث:** یک print آزمایشی به server اضافه کنید و اثر خراب شدن ارتباط را توضیح دهید؛ سپس آن را حذف کنید. خطای ابزار باید در قرارداد پروتکل برگردد، نه با متن پراکنده در خروجی.

## 8. اعتبارسنجی و محدودسازی — دقیقهٔ 35 تا 40

- query طول محدود و limit بازهٔ کوچک دارد
- مسیر فایل از ورودی کاربر ساخته نمی‌شود
- URL دلخواه کاربر را بدون allowlist fetch نکنید

**راهنمای اجرا و بحث:** خطر SSRF را با آدرس metadata توضیح دهید. server نمونه محتوای محلی مشخص را می‌خواند؛ عامل نمی‌تواند با query به فایل‌های بیرون از مجموعه دسترسی بگیرد.

## 9. خطاهای ابزار — دقیقهٔ 40 تا 45

- ورودی نامعتبر، مجوز ناکافی و نبود نتیجه متفاوت‌اند
- نبود نتیجه الزاماً خطای server نیست
- stack trace و secret را به مدل ندهید

**راهنمای اجرا و بحث:** برای query بدون تطابق، لیست خالی را نتیجهٔ معتبر بدانید. برای limit نامعتبر، schema باید درخواست را رد کند. این دو وضعیت را در آزمون تفکیک کنید.

## 10. دسترسی و اختیار — دقیقهٔ 45 تا 50

- مجوز را با هویت کاربر روی server بسنجید
- read و write دامنه‌های جدا دارند
- تأیید رابط کاربر جای authorization نیست

**راهنمای اجرا و بحث:** مثال انتشار صفحه را طرح کنید. حتی اگر مدل ابزار publish را انتخاب کند، server باید scope و مالکیت را بررسی کند. annotation مثل readOnlyHint تضمین امنیت نیست.

## 11. معماری MCP وب‌سایت — دقیقهٔ 50 تا 55

- عامل از client به catalog server می‌رسد
- server فقط محتوای دوره را می‌بیند
- دادهٔ برگشتی عنوان و شناسهٔ قابل بررسی دارد

**راهنمای اجرا و بحث:** روی نمودار مرز فرایند را نشان دهید. سرور به کل filesystem اختیار نمی‌دهد. محدود کردن دادهٔ قابل دسترس ساده‌تر و قوی‌تر از درخواست شفاهی «مراقب باش» است.

## 12. نمایش زنده: server رسمی SDK — دقیقهٔ 55 تا 60

- FastMCP schema را از type hint می‌سازد
- دو ابزار و یک resource در نمونه موجود است
- Client واقعی چرخهٔ initialize و call را اجرا می‌کند

**راهنمای اجرا و بحث:** فایل server.py را باز کنید و نام ابزارها را با خروجی list_tools تطبیق دهید. server در این مرحله به API مدل نیاز ندارد. اجرای محلی با کلاینت SDK کافی است.

## 13. آزمایشگاه: محیط Python — دقیقهٔ 60 تا 65

- محیط مجازی بسازید و requirements را نصب کنید
- python labs/session-3/smoke.py را اجرا کنید
- خروجی باید catalog، search و resource را تأیید کند

**راهنمای اجرا و بحث:** نصب وابستگی شبکه لازم دارد ولی اجرای خود سرور بعد از نصب آفلاین است. اگر نصب شکست خورد، علت TLS یا نسخه را حل کنید؛ آن را با غیرفعال کردن دائمی بررسی گواهی حل نکنید.

## 14. آزمایشگاه: ابزار جستجو — دقیقهٔ 65 تا 70

- عبارت MCP را جستجو کنید
- تعداد خروجی را به یک نتیجه محدود کنید
- شناسه و عنوان را با content/course.json تطبیق دهید

**راهنمای اجرا و بحث:** فراگیر باید نتیجه را از دادهٔ واقعی دوره تشخیص دهد. جستجو substring است و ادعای جستجوی معنایی ندارد. برای فارسی حروف ی و ک را یکسان‌سازی کنید.

## 15. آزمایشگاه: resource — دقیقهٔ 70 تا 75

- URI course://syllabus را بخوانید
- مدت هر جلسه را از JSON استخراج کنید
- جمع زمان باید ۷۲۰ دقیقه باشد

**راهنمای اجرا و بحث:** این تمرین نشان می‌دهد resource فقط یک متن تزئینی نیست. ساختار داده باید برای مصرف ماشینی هم معتبر باشد. اگر مدت تغییر کرد، validator کل سایت نیز باید شکست بخورد.

## 16. آزمایشگاه: اتصال به Codex — دقیقهٔ 75 تا 80

- server را با مسیر مطلق ثبت کنید
- codex mcp list وضعیت تنظیم را نشان می‌دهد
- درخواست جستجو را با نام ابزار مشخص اجرا کنید

**راهنمای اجرا و بحث:** دستور در راهنمای آزمایشگاه آمده است. cwd میزبان را فرض نکنید؛ server مسیر داده را نسبت به __file__ پیدا می‌کند. خروجی اتصال به حساب و نسخهٔ نصب‌شده وابسته است.

## 17. آزمایشگاه: اتصال به Claude — دقیقهٔ 80 تا 85

- claude mcp add --transport stdio از فرایند محلی استفاده می‌کند
- همان Python و server را معرفی کنید
- schema و تعداد نتایج را با Codex مقایسه کنید

**راهنمای اجرا و بحث:** در هر میزبان باید اعتماد server و مجوز ابزار را جدا بررسی کرد. فایل تنظیم میزبان‌ها یکسان نیست. اگر Claude نصب نیست، smoke client همان قرارداد را به‌صورت مستقل می‌سنجد.

## 18. OAuth در MCP شبکه‌ای — دقیقهٔ 85 تا 90

- توکن برای resource و audience درست صادر می‌شود
- PKCE و metadata در جریان استاندارد مهم‌اند
- توکن سرویس پایین‌دستی را کورکورانه عبور ندهید

**راهنمای اجرا و بحث:** جریان authorization را مفهومی تدریس کنید. نمونهٔ STDIO ما OAuth server پیاده نمی‌کند. این مرز را صریح بگویید تا فراگیر سرور آموزشی را آمادهٔ اینترنت نداند.

## 19. حدود اعتماد در پاسخ ابزار — دقیقهٔ 90 تا 95

- محتوای صفحه ممکن است دستور تزریقی داشته باشد
- پاسخ tool را به‌عنوان داده با منبع نگه دارید
- scope نوشتن از متن برگشتی ساخته نمی‌شود

**راهنمای اجرا و بحث:** یک عنوان آلوده را فرض کنید که درخواست حذف فایل می‌دهد. وظیفهٔ host این است که داده را از دستور معتبر جدا کند. سرور نیز نباید ابزار shell عمومی ارائه کند.

## 20. تغییرات سازگار schema — دقیقهٔ 95 تا 100

- حذف یا تغییر نوع فیلد می‌تواند client را بشکند
- افزودن فیلد اختیاری معمولاً کم‌ریسک‌تر است
- قرارداد و smoke test را نسخه‌بندی کنید

**راهنمای اجرا و بحث:** به limit مقدار پیش‌فرض بدهید و client قدیمی را بدون ارسال limit اجرا کنید. سپس توضیح دهید تغییر پیش‌فرض هم می‌تواند رفتار کسب‌وکار را عوض کند و باید مستند شود.

## 21. مشاهده‌پذیری ابزار — دقیقهٔ 100 تا 105

- زمان، نام ابزار و وضعیت را ثبت کنید
- query خصوصی و credential را log نکنید
- request ID برای اتصال رخدادها مفید است

**راهنمای اجرا و بحث:** سه شاخص پیشنهاد دهید: نرخ خطا، p95 latency و اندازهٔ پاسخ. پاسخ بزرگ حتی با latency کم می‌تواند هزینهٔ زمینه را بالا ببرد. جلسهٔ چهارم این موضوع را ادامه می‌دهد.

## 22. بازیابی و timeout — دقیقهٔ 105 تا 110

- درخواست خواندنی قابل retry محدود است
- عملیات نوشتن idempotency key می‌خواهد
- قطع client نباید عملیات نامعلوم را بی‌ردپا بگذارد

**راهنمای اجرا و بحث:** مثال publish را با search مقایسه کنید. retry جستجو معمولاً امن‌تر است؛ retry پرداخت یا انتشار بدون شناسه می‌تواند اثر تکراری بسازد. حالت unknown را از failed تفکیک کنید.

## 23. سنجش: امنیت transport — دقیقهٔ 110 تا 115

- انتخاب transport تعیین‌کنندهٔ مدل تهدید است
- STDIO محلی و HTTP عمومی یکسان نیستند
- authorization باید سمت سرویس اعمال شود

**راهنمای اجرا و بحث:** از کلاس بخواهید علت رد گزینه‌های دیگر را بگوید. هدف حفظ اصطلاح OAuth نیست؛ تشخیص مرز اعتبارسنجی و جلوگیری از دسترسی بدون اختیار است.

## 24. تحویل جلسهٔ سوم — دقیقهٔ 115 تا 120

- server، smoke client و schema معتبر
- نتیجهٔ جستجو و خواندن resource با شاهد
- محدودیت‌ها و مدل تهدید در README

**راهنمای اجرا و بحث:** برای تحویل کامل، query بدون نتیجه و limit نامعتبر را نیز نشان دهید. اتصال موفق به یک میزبان کافی است و smoke test باید مستقل از مدل پاس شود.
