# آزمایشگاه 1 — مهندسی نشست و قرارداد

## پیش از کلاس
Node.js 22 یا بالاتر، Python 3.11 یا بالاتر و Git لازم است. تمرین را در یک checkout آموزشی اجرا کنید. هیچ کلید یا فایل ورود را commit نکنید. همهٔ فرمان‌ها از ریشهٔ مخزن هستند مگر مسیر دیگری ذکر شود. فایل‌های کامل و پاسخ مرجع همراه تمرین‌اند؛ فعالیت کلاس بازبینی، تغییر کنترل‌شده و آزمون شکست است.

## هدف و خروجی
یک نشست قابل ادامه با قرارداد روشن، آزمون رفتاری و checkpoint بسازید. خروجی: prompt.md، گزارش آزمون و یادداشت تصمیم. زمان فعالیت: اسلایدهای ۱۶ تا ۲۰، مجموع ۲۵ دقیقه.
## گام‌ها — هر گام ۵ دقیقه
1. وارد labs/session-1 شوید. AGENTS.md و subtotal.mjs را بخوانید. آزمون خط پایه را اجرا کنید.
2. prompt.md را بازبینی کنید. مثال اعشاری و منع تبدیل رشته را حفظ کنید؛ یک مثال خودتان اضافه کنید.
3. آزمون subtotal برای ورودی آرایه‌نبودن بنویسید. پیش از تغییر پیاده‌سازی، نتیجهٔ واقعی را ثبت کنید.
4. از الگوی checkpoint.example.md یک یادداشت برای همکار بسازید. هدف، تصمیم، شاهد و قدم بعدی لازم است.
5. اگر CLI رسمی و حساب مجاز دارید، درخواست خواندنی را اجرا و سپس نشست را ادامه دهید. در غیر این صورت یک هم‌گروهی فقط با checkpoint کار را ادامه دهد.
```sh
cd labs/session-1
npm test
codex --version
codex login status
codex exec --sandbox read-only "Read AGENTS.md and review subtotal; do not edit files"
codex resume --last
```
## نتیجهٔ مورد انتظار و پاسخ مرجع
چهار آزمون موجود باید پاس شوند. تابع برای [1.5,2.25] مقدار 3.75 می‌دهد و NaN، Infinity، رشته و عدد منفی را رد می‌کند. برای افزودن آزمون آرایه‌نبودن می‌توانید assert.throws(() => subtotal(null), TypeError) بنویسید؛ پیاده‌سازی موجود باید آن را پاس کند. تغییر کد بدون نیاز امتیاز اضافه ندارد.
## تشخیص خطا
اگر npm test از ریشه اجرا شد، آزمون‌های کل پروژه را می‌بینید؛ در این تمرین مسیر جاری labs/session-1 است. اگر login معتبر نیست، فرمان مدل را متوقف کنید و مسیر آفلاین را ادامه دهید. read-only اجازهٔ تغییر فایل نمی‌دهد؛ درخواست ویرایش باید در مخزن مورد اعتماد و با اختیار صریح workspace-write انجام شود.
## معیار تحویل
قرارداد ورودی دقیق، حداقل یک آزمون لبهٔ افزوده، خروجی واقعی آزمون و checkpoint قابل استفاده توسط نفر دوم. گزارش باید بگوید اجرای زندهٔ مدل انجام شده یا فقط مسیر آفلاین تأیید شده است.

## دموی جذاب کلاس: ادامهٔ پروژهٔ محلی Claude Code در Codex
دو مسیر داریم: ورود پشتیبانی‌شده با /import و تحویل گزینشی با HANDOFF.md. این قسمت از پروژهٔ قبلی واقعی کلاس استفاده می‌کند؛ فایل‌های مخزن دورهٔ قبلی را در این مخزن تغییر نمی‌دهیم. دانشجو باید همان پوشهٔ محلی پروژهٔ خودش را باز کند. گردش‌کار زیر انتقال زمینه و وضعیت قابل بررسی است؛ واردکردن شناسه یا تمام تاریخچهٔ داخلی یک محصول به محصول دیگر ادعا نمی‌شود.

1. در نشست فعلی Claude Code، متن handoff-source.prompt.md را بدهید تا HANDOFF.md در ریشهٔ همان پروژه نوشته شود.
2. فایل را بخوانید. هدف، تصمیم، فایل مرتبط، وضعیت Git، آزمون و قدم بعدی باید قابل بررسی باشند. اگر آزمون اجرا نشده، همین را بنویسید. نمونهٔ آموزشی HANDOFF.example.md برای فهم قالب است و گزارش واقعی شما نیست.
3. ویرایش عامل اول را متوقف کنید. از ترمینال همان پوشه Codex را باز کنید. برای بررسی اولیهٔ خواندنی:
```sh
codex --sandbox read-only "Read HANDOFF.md and the applicable project instructions. Compare the handoff with the current files, git status and git diff. Do not edit anything. Explain the goal, discrepancies and the next step."
```
4. یا متن کامل handoff-target.prompt.md را در نشست تازهٔ Codex بدهید. عامل گیرنده باید پیش از ادامه وضعیت واقعی را تطبیق دهد. اگر به تغییر فایل رسیدید، اختیار نوشتن را جدا و آگاهانه مطابق محیط و قرارداد کار انتخاب کنید.

دستور codex resume برای ادامهٔ نشست ذخیره‌شدهٔ Codex است. در این دمو یک نشست تازهٔ Codex، فایل تحویل را می‌خواند. تنظیمات، اتصال MCP، احراز هویت و اطلاعات پنهان نشست Claude Code همراه فایل Markdown به‌صورت خودکار منتقل نمی‌شوند.

## checkpoint در این تمرین چه معنی دارد؟
فقط یک یادداشت وضعیت برای ادامهٔ کار: هدف، تصمیم، انجام‌شده، نتیجهٔ آزمون و قدم بعدی. اسم فایل الزامی نیست؛ HANDOFF.md یا checkpoint.md انتخاب آموزشی ماست. Checkpointer در یک چارچوبی مانند LangGraph سازوکار فنی ذخیره و بازیابی state است؛ این تمرین آن کتابخانه یا سازوکار را پیاده نمی‌کند.

لاگ می‌گوید هنگام اجرا چه اتفاقی افتاده است. یادداشت تحویل می‌گوید اکنون کجا هستیم و چه کاری باید ادامه پیدا کند. خلاصه‌سازی متن را کم می‌کند؛ یادداشت خوب علاوه بر کوتاه‌بودن، وضعیت عملی کار را حفظ می‌کند.

## config.toml را خط‌به‌خط بخوانید
TOML یک قالب فایل متنی ساختاریافته است. در نام config.toml، بخش config یعنی تنظیمات و پسوند toml یعنی قالب نوشتن آن تنظیمات. این فایل تاریخچهٔ نشست یا یادداشت تحویل نیست.
```toml
sandbox_mode = "read-only"
approval_policy = "on-request"
```
خط اول محدودهٔ اجرای نمونه را خواندنی می‌کند؛ خط دوم رفتار درخواست تأیید را تعیین می‌کند و خودش اجازهٔ نوشتن نمی‌دهد. تنظیمات شخصی Codex در ~/.codex/config.toml هستند؛ پروژهٔ مورد اعتماد می‌تواند .codex/config.toml داشته باشد. تنظیم‌های واقعی کاربر را برای تمرین بازنویسی نکنید؛ نمونه را بخوانید یا از گزینهٔ صریح فرمان استفاده کنید.

منابع: [پیکربندی Codex](https://learn.chatgpt.com/docs/config-file/config-basic)، [فرمان‌های Codex](https://learn.chatgpt.com/docs/developer-commands?surface=cli)، [حافظهٔ پروژه در Claude Code](https://code.claude.com/docs/en/memory)، [قالب TOML](https://toml.io/en/)، [ذخیرهٔ وضعیت در LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence).

## انتخاب Fork و قابلیت‌های نزدیک — اسلایدهای ۱۱ و ۱۲
پیش از کلاس نسخه و محیط را ثبت و فهرست فرمان‌های همان نصب را بررسی کنید. جدول مقایسه برای CLIهاست؛ یکسان‌بودن نام، رفتار یکسان در همهٔ ابزارها یا نسخه‌ها را تضمین نمی‌کند.

| ابزار | دستور داخل نشست | رفتار |
| --- | --- | --- |
| Codex | /fork | کپی چت فعلی با شناسهٔ تازه |
| Claude Code | /branch alternative-filter | رفتن به شاخهٔ گفت‌وگو با حفظ اصل |
| Claude Code | /fork | کپی برای کار پس‌زمینه در حالت مستند فعلی |
| Antigravity CLI | /fork | شاخه‌کردن گفت‌وگو با حفظ workspace |

دموی خواندنی: در مسیر اول دربارهٔ فیلتر دکمه‌ای صحبت کنید، سپس یک شاخه بسازید و فقط طراحی فهرست انتخاب را بخواهید. به گفت‌وگوی اصلی برگردید و تفاوت دو پیشنهاد را توضیح دهید. قبل از نوشتن همزمان روی کد، فایل‌ها را با worktree یا checkout جدا کنید؛ Fork به‌تنهایی جداسازی فایل را تضمین نمی‌کند.

تمرین تشخیصی: ادامهٔ دیروز → Resume؛ مسئلهٔ تازه → New/Clear؛ روش جایگزین با سابقهٔ مشترک → Fork/Branch؛ گفت‌وگوی طولانی → Compact؛ آزمایش مستقل تغییر فایل → Worktree. برای پرسش کوتاه جانبی، نمونهٔ Codex /side و Claude Code /btw است. Rewind را فقط در محدودهٔ مستند محصول به کار ببرید؛ برگشت همهٔ فایل‌ها و اثرهای خارجی را تضمین نمی‌کند.

## مسیر رسمی Import در Codex — تکمیل توضیح قبلی
در یک نشست بیکار Codex CLI، /import را اجرا کنید، Claude Code را انتخاب و سپس موارد پشتیبانی‌شده را مرور و انتخاب کنید. طبق مستند فعلی CLI تا ۵۰ چت از ۳۰ روز اخیر جستجو می‌کند. پس از ورود، یک چت یا پروژه را باز کنید و تنظیم‌ها، فایل‌ها و اتصال‌های نیازمند تکمیل را بررسی کنید. در اتصال به daemon یا server، جستجو روی ماشین همان server انجام می‌شود. اگر فرمان در نصب شما موجود نبود، از روش HANDOFF.md بالا استفاده کنید.

وجود /import در بررسی جدید مستندات تأیید شد؛ توضیح قبلی درس فقط روش عمومی HANDOFF را پوشش می‌داد. واردکردن موارد پشتیبانی‌شده با ادعای انتقال تمام حافظهٔ پنهان، ورودها و رفتار یکسان همهٔ ابزارها برابر نیست. در این پروژه هیچ نشست یا تنظیم خصوصی شما وارد نشده است.
