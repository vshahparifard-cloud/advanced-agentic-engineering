# آزمایشگاه 2 — مهارت، پلاگین و hook

## پیش از کلاس
Node.js 22 یا بالاتر، Python 3.11 یا بالاتر و Git لازم است. تمرین را در یک checkout آموزشی اجرا کنید. هیچ کلید یا فایل ورود را commit نکنید. همهٔ فرمان‌ها از ریشهٔ مخزن هستند مگر مسیر دیگری ذکر شود. فایل‌های کامل و پاسخ مرجع همراه تمرین‌اند؛ فعالیت کلاس بازبینی، تغییر کنترل‌شده و آزمون شکست است.

## تفاوت AGENTS.md و Skill در همین تمرین
AGENTS.md راهنمای کار عامل در محدودهٔ پروژه است: مثلاً متن سایت فارسی و RTL بماند، زمان هر جلسه ۱۲۰ دقیقه باشد و تغییرها با آزمون تأیید شوند. Skill روش انجام یک وظیفهٔ مشخص را نگه می‌دارد: مثلاً چگونه یک ارائهٔ آموزشی یا یک گزارش review ساخته و بررسی شود.

| بخش | پرسشی که پاسخ می‌دهد | مثال |
| --- | --- | --- |
| پیام چت | الان چه کاری انجام بده؟ | ارائهٔ جلسهٔ پنجم را بساز |
| AGENTS.md | هنگام کار در این پروژه چه قواعدی رعایت شود؟ | فارسی و RTL، زمان جلسه و فرمان آزمون |
| Skill | این کار تخصصی را با چه مراحلی انجام بده؟ | هدف، منبع رسمی، اسلاید، یادداشت، تمرین و بازبینی |

هر دو می‌توانند دستور متنی داشته باشند و محتوایشان هم‌پوشانی داشته باشد. تفاوت صرفاً متن نیست: AGENTS.md طبق مسیر و دامنهٔ پروژه در شروع اجرا کشف می‌شود؛ از مهارت‌ها ابتدا نام و description دیده می‌شود و متن کامل مهارت هنگام انتخاب خوانده می‌شود. انتخاب مهارت می‌تواند با درخواست مستقیم یا تشخیص ارتباط با وظیفه باشد. برای یک قاعدهٔ کوتاه و مشترک، راهنمای پروژه مناسب است؛ برای روش تخصصی چندمرحله‌ای که فقط گاهی لازم است، مهارت متمرکز معمولاً مناسب‌تر است. اسکریپت در Skill اختیاری است و هیچ‌کدام جای مجوز واقعی محیط اجرا را نمی‌گیرند.

تمرین تشخیصی: «همیشه متن سایت فارسی باشد»، «ابتدا هدف آموزشی را مشخص کن و سپس اسلاید بساز» و «امروز جلسهٔ پنجم را آماده کن» را دسته‌بندی کنید. پاسخ به‌ترتیب: AGENTS.md، روش Skill و پیام چت. در مثال عملی این آزمایشگاه، AGENTS.md جلسهٔ اول قرارداد تابع و آزمون را نگه می‌دارد؛ مهارت review-evidence مراحل تولید گزارش بازبینی را تعریف می‌کند.

توضیح و جدول در اسلایدهای ۱ تا ۵ جلسهٔ دوم و تمرین تعاملی در اسلاید ۴ آمده است. منابع رسمی: [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) و [Skills](https://learn.chatgpt.com/docs/build-skills).

## هدف و خروجی
یک مهارت بازبینی محدود را نصب و معیار انتخاب و گزارش آن را ارزیابی کنید. خروجی: SKILL.md بازبینی‌شده، شش prompt آزمون انتخاب و یک گزارش پذیرفته‌شده. زمان: ۲۵ دقیقه.
## گام‌ها — هر گام ۵ دقیقه
1. skill/SKILL.md را بخوانید و در مخزن تمرینی خود در مسیر .agents/skills/review-evidence/SKILL.md کپی کنید. نصب در پروژهٔ آموزشی باشد.
2. سه درخواست review مرتبط و سه درخواست نامرتبط مانند ترجمه، طراحی لوگو و نوشتن شعر بسازید. انتخاب مورد انتظار را ثبت کنید.
3. validator را روی report.json اجرا کنید؛ سپس tests را حذف یا خالی کنید و رد شدن را ببینید.
4. دو نقش پیشنهاددهنده و بازبین تعریف کنید. مالک فایل، اختیار خواندن و قالب گزارش هر نقش را بنویسید. با زیرعامل رسمی میزبان یا دو نفر مستقل اجرا کنید.
5. دو گزارش متناقض را با آزمون حل کنید و گزارش نهایی را اعتبارسنجی کنید.
```sh
node labs/session-2/validate.mjs labs/session-2/report.json
node --test labs/session-2/validate.test.mjs
```
## پاسخ و شواهد مورد انتظار
گزارش معتبر پیام Report accepted و کد صفر دارد. گزارش فاقد tests باید با Missing evidence: tests و کد غیرصفر تمام شود. prompt «این diff را با شواهد آزمون review کن» مثبت و «یک شعر دربارهٔ تست بنویس» منفی است. تطابق یک کلمهٔ test برای فعال‌سازی کافی نیست.
## تمرین تکمیلی hook
edit_guard.py یک hook آموزشی Claude برای ابزار Edit است. نمونهٔ تنظیم در claude.settings.example.json آمده؛ برای تست بدون نصب:
```sh
python3 -c 'import json; print(json.dumps({"tool_name":"Edit","tool_input":{"file_path":"/demo/.env"}}))' | python3 labs/session-2/edit_guard.py
```
کد خروج باید ۲ باشد. فایل معمولی مثل /demo/app.py کد صفر دارد. hook پوشش کامل نوشتن با Bash یا ابزار دیگر ندارد و مرز امنیتی نیست. مسیر command را متناسب با ریشهٔ پروژه تنظیم کنید.
## بستهٔ پلاگین
plugin/.codex-plugin/plugin.json و پوشهٔ skills یک بستهٔ نمونهٔ محلی‌اند. این ساختار را با نسخهٔ فعلی میزبان و مستند رسمی بسته‌بندی تطبیق دهید؛ فرمت را به Claude تعمیم ندهید. انتشار در marketplace بخشی از این تمرین نیست.
## معیار تحویل
شش نمونهٔ انتخاب با دلیل، گزارش معتبر، یک شکست validator و توضیح صریح محدودیت hook. وجود ساختار معتبر، کیفیت محتوایی گزارش را به‌تنهایی اثبات نمی‌کند.
